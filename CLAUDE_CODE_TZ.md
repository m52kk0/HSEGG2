## 0. Контекст

Хакатон «Сервис для абитуриента». Защита — через 1–2 дня. Команда — один человек + ИИ.

Задание: кликабельный MVP с тестовыми данными, по которому **можно пройти сценарий целиком**. Сервис должен помогать абитуриенту **разобраться и принять решение**, а не повторять подачу документов (Госуслуги) и не быть ещё одним каталогом (Vuzopedia, Postupi.online).

Критерии оценки жюри, **в порядке важности**:
1. **Согласованность интерфейса и интуитивная понятность** — интерфейс работает по единым правилам, пользователь понимает его без инструкции.
2. **Проработанность демо** — сценарий проходится целиком.
3. **Защита** — каждое решение (добавленное и убранное) объяснимо.
4. **Преимущество** над существующими сервисами.

Отсюда главное правило приоритетов: **качество интерфейса > работоспособность сценария > бэкенд > тесты > документация**. Если время кончается — режь снизу.

## 1. Продукт в одной фразе

**Cursus** (лат. «путь, курс») отвечает не на вопрос «куда я могу поступить?», а на вопрос **«как мне поступить наилучшим образом и не остаться без бюджета?»**.

Справочник показывает, какие дороги существуют. Cursus строит маршрут.

### Что делаем (и почему)
- **Автоматический план поступления** по правилам 2026: до 5 вузов × до 5 направлений в каждом, порядок направлений внутри каждого вуза.
- **Зоны «Мечта / Цель / Запасной»** вместо процентов «шанса».
- **Запас баллов** («+12» / «−8») относительно прогноза проходного.
- **Предупреждения о рисках** плана (нет запасного варианта и т. п.).
- **Карточка направления** с «Похожими направлениями» и короткой разницей между ними.
- **Сравнение** до 3 направлений.
- **План Б** — что делать, если не прошёл никуда.
- **Реальные данные рынка труда**: зарплаты выпускников (Росстат) и живые вакансии (API «Работа России»).
- **Собственная анонимная аналитика** с экраном воронки.

### Чего НЕ делаем (и почему)
- Каталог всех вузов с фильтрами — есть у всех конкурентов.
- Профориентационные тесты — есть у Vuzopedia/Postupi.
- Подачу документов, авторизацию через Госуслуги — это Госуслуги.
- Проценты «шанс 55%» — по открытым данным их нельзя честно посчитать.
- Drag-and-drop — неудобно на телефоне.
- Регистрацию, аккаунты, личные данные — не нужны для ценности, создают риски по 152-ФЗ.

## 2. Предметная область: правила приёма (бакалавриат/специалитет, 2026)

Логика продукта обязана соответствовать этим правилам:
- Абитуриент подаёт документы **не более чем в 5 вузов**, в каждом — **не более чем на 5 направлений** (специальностей/групп).
- **Приоритеты расставляются внутри каждого вуза отдельно** (1 — самое желанное).
- Зачисляют на направление **с наивысшим приоритетом, на которое абитуриент проходит по конкурсу**. Поэтому ставить «Мечту» на приоритет 1 — **бесплатно**: если не пройдёт, зачислят на следующий приоритет. Порядок = порядок желания. Это ключевой инсайт для подсказок в интерфейсе.
- Приоритеты можно менять до **25 июля**, после — нельзя.
- **Согласие на зачисление** — только в один вуз на одно направление.
- Дополнительный набор — примерно с **12 августа** (вузы с незаполненными местами).
- Приём в колледжи на свободные места — до **25 ноября**. Результаты ЕГЭ действительны **4 года**.

Все даты вынести в `packages/core/src/config/campaign.ts` с комментарием `// Даты по правилам 2026; даты кампании 2027 уточняются` и показывать в интерфейсе с пометкой «по правилам 2026 года».

MVP учитывает **только общий конкурс на бюджет**. Целевая/особая/отдельная квоты, БВИ и внутренние экзамены — вне скоупа (упомянуть в документации).

## 4. Алгоритм (пакет `packages/core`)

Чистые функции без побочных эффектов, 100% покрытие тестами.

### 4.1. Балл абитуриента для программы
```
examScore(program, user) =
  сумма по 3 экзаменам программы; для экзамена с альтернативой берётся лучший из сданных пользователем
  + min(user.achievementsBonus, 10)       // индивидуальные достижения, максимум 10
eligible = пользователь сдавал все нужные предметы И каждый балл ≥ minScores
```
Если не `eligible` → программа не попадает в план; в поиске показывается с меткой «Не подходит: нет физики» / «Не подходит: информатика ниже минимума 44».

### 4.2. Прогноз проходного
```
trend = clamp(((c2025 - c2024) + (c2024 - c2023)) / 2, -10, +15)
predictedCutoff = round(c2025 + trend)
margin = examScore - predictedCutoff
```
Если есть только часть лет — использовать то, что есть; если только один год — `trend = 0`.

### 4.3. Зона
```
margin >= +10          → "safe"    («Запасной»)
-5 <= margin < +10     → "target"  («Цель»)
margin < -5            → "reach"   («Мечта»)
```
Пороги — в `config/zones.ts`, экспортируются и документируются в `ALGORITHM.md`.

### 4.4. Сборка плана `buildPlan(user, programs, universities)`
1. Отфильтровать `eligible` программы в выбранных регионах (или по всей РФ, если выбрано «Любой»), по интересам пользователя (группы направлений).
2. Сгруппировать по вузам. Оценить вуз: наличие хотя бы одной `target`/`safe` программы по интересам, число подходящих программ, близость к городу пользователя.
3. Выбрать **до 5 вузов** так, чтобы план в целом содержал **хотя бы 1–2 вуза с `safe`-программой** и хотя бы одну `reach`, если такая есть (мечтать бесплатно).
4. Внутри вуза выбрать **до 5 программ** и упорядочить: сначала по совпадению с интересами пользователя (порядок интересов важен), затем `reach` → `target` → `safe` (желаннее — выше). Нумерация = приоритет.
5. Вернуть `Plan { universities: PlanUniversity[], verdict, warnings, simulation }`.

### 4.5. Вердикт (одна фраза сверху экрана)
- есть ≥ 2 `safe` в разных вузах → **«Бюджет почти гарантирован»** (зелёный)
- есть 1 `safe` → **«Бюджет вероятен, но добавь ещё запасной вариант»** (жёлтый)
- нет `safe`, есть `target` → **«Рискованно: все варианты впритык»** (жёлтый)
- только `reach` → **«Высокий риск остаться без бюджета»** (красный)
- план пуст → **«Под твои баллы бюджетных мест не нашлось»** + ведём в План Б

### 4.6. Предупреждения (`warnings`)
- нет ни одного `safe` → «Добавь запасной вариант — направление с запасом от 10 баллов»;
- в вузе приоритет 1 — `safe`, а ниже стоят `reach` → «Направления ниже приоритета 1 никогда не сработают, если ты проходишь на первое. Поставь самое желанное первым»;
- выбрано меньше 3 вузов при наличии вариантов → «Можно подать ещё в N вуза — это бесплатно увеличивает шансы»;
- программа с `isDemo` — предупреждений не даёт (метка «Демо» отдельно).

### 4.7. Симуляция «Что будет, если…» (`simulation`)
Для каждого вуза — цепочка: «Приоритет 1 (Мечта) — вероятно не пройдёшь → Приоритет 2 (Цель) — на грани → Приоритет 3 (Запасной) — проходишь». Итог по вузу: «Скорее всего зачислят на: <название>». Это текстовая модель на основе зон, не вероятностная.

## 5. UX: принципы («пользователь ничего не знает о приёме»)

1. **Одно главное действие на экран** — одна синяя кнопка.
2. **Сначала ответ, потом детали**: вердикт → причина → данные.
3. **Код направления всегда рядом с названием** (`15.03.04 · Автоматизация технологических процессов и производств`). Абитуриенты, родители и приёмные комиссии говорят кодами. Поиск работает и по коду, и по названию.
4. **Термины** («приоритет», «согласие на зачисление», «допнабор», «УГСН») — только с иконкой «?» и понятным тултипом. Везде, где можно, обычные слова: «Хочу больше всего» рядом с «Приоритет 1».
5. **Цвет никогда не единственный носитель смысла**: цветная точка + слово («Запасной»).
6. **Нет пустых экранов**: у каждого пустого состояния есть текст и действие.
7. **Ошибки предупреждаются заранее**, а не после действия.
8. **Числа — с единицами и знаком**: «+12 баллов», «72 тыс. ₽», «82% трудоустроены».
9. **Мобильные первыми**: 360px ширины без горизонтального скролла, тач-цели ≥ 44px.
10. **Всё управляется с клавиатуры**, видимый фокус.

## 6. Экраны и навигация

Навигация: две вкладки — **«Мой план»** и **«Найти»** (на мобильном — нижний таб-бар, на десктопе — в шапке справа). Логотип Cursus слева.

Роутинг (React Router): `/` (онбординг или редирект на `/plan`, если профиль есть), `/onboarding/:step`, `/plan`, `/search`, `/program/:id`, `/compare?ids=a,b,c`, `/plan-b`, `/admin`.

Состояние пользователя (профиль, план, список сравнения, id сессии) — Zustand + `localStorage` (обернуть чтение/запись в try/catch). Кнопка «Начать заново» в профиле.

### 6.1. Онбординг — 4 шага, по одному вопросу на экран
Прогресс-бар сверху («Шаг 2 из 4»), кнопка «Назад», одна кнопка «Дальше» (неактивна, пока нет ответа).

1. **«Какие ЕГЭ ты сдаёшь?»** — плитки предметов (мультивыбор). Русский выбран и заблокирован с подписью «обязательный».
2. **«Сколько баллов?»** — поле на каждый выбранный предмет (0–100, валидация). Переключатель «Ещё не сдавал — ввести ожидаемые». Чекбоксы достижений: «Золотая медаль / аттестат с отличием», «Знак ГТО», «Волонтёрство», «Итоговое сочинение с отличием» → суммарный бонус (с подсказкой «Каждый вуз засчитывает по-своему, максимум 10 баллов»).
3. **«Что тебе интересно?»** — 6–8 крупных плиток-групп («IT и программирование», «Инженерия и производство», «Энергетика», «Экономика и управление», «Медицина», «Педагогика», «Естественные науки», «Гуманитарные и право»). Можно выбрать до 3; порядок выбора = важность (показывать номер на плитке).
4. **«Где готов учиться?»** — «В своём регионе» (выбор региона из `regions.json`, поиск), «Ещё в нескольких регионах» (мультиселект), «Где угодно в России».

Финальная кнопка: **«Построить план»** → экран загрузки ≤ 1 с («Сравниваем N вузов…», N — реальное число из снимка) → `/plan`.

### 6.2. «Мой план» (главный экран)
Сверху вниз:
1. **Вердикт** — крупная фраза (H1), цветная точка, одна строка пояснения («2 вуза с запасом, 1 — впритык»).
2. **Предупреждения** — если есть: аккуратные плашки с действием («Добавить запасной»).
3. **Карточки вузов** (до 5). В заголовке — название вуза, город, мини-итог «Скорее всего зачислят на: …». Внутри — нумерованный список направлений:
   `1 · Хочу больше всего` / `15.03.04 · Автоматизация…` / зона + «+3 балла» / кнопки ↑ ↓ ✕.
   Кнопки: «Добавить направление в этот вуз» (открывает список подходящих программ этого вуза), «Убрать вуз».
   Раскрывающийся блок **«Что будет, если…»** — цепочка из 4.7.
4. **«Добавить вуз»** — если вузов < 5.
5. **«Если не пройду никуда»** — свёрнутая плашка → `/plan-b`.
6. **«Что сделать сейчас»** — 1–3 задачи с датами («До 25 июля — зафиксировать порядок направлений», «Подать документы через Госуслуги»). Ссылка «Как подать на Госуслугах» (внешняя).
7. **«Поделиться планом»** — копирует ссылку с зашифрованным в query профилем (base64url JSON) + кнопка «Скачать план» (печать страницы через `window.print()` со стилями `@media print`).

Любое изменение плана пересчитывает вердикт и предупреждения мгновенно, с короткой анимацией (≤ 200 мс, `prefers-reduced-motion` уважать).

### 6.3. «Найти»
Одно поле поиска: «Код или название направления, вуз». Результаты — список направлений (группировка по коду), под каждым — сколько вузов в выбранных регионах и диапазон зон. Фильтры-чипы: «Только подходящие мне», «Только с запасом», регион. Клик → `/program/:id` (для лучшего вуза в регионе) с переключателем вуза.

### 6.4. Карточка направления `/program/:id`
1. Шапка: `15.03.04` · название · вуз, город. Зона + запас. Кнопка **«Добавить в план»** (или «В плане ✓»).
2. **«Сколько нужно баллов»** — мини-график проходных 2023–2025 + пунктир прогноза + горизонтальная линия «твой балл». Метка «Демо». Бюджетных мест. Экзамены и минимумы, у непройденного — красная строка.
3. **«Чему научат»** (если есть текст).
4. **«Кем будешь работать»** — 3 профессии; «Зарплата выпускников в <регионе>: через год 72 тыс. ₽, через 5 лет 90 тыс. ₽, трудоустроены 82%» (фолбэк на `RU`, если по региону нет, с подписью «по России»). Источник мелким шрифтом.
5. **«Вакансии сейчас»** — число вакансий и 3 примера (должность, работодатель, зарплата) из API «Работа России» по `vacancyQuery` и коду региона. Скелетон при загрузке; при ошибке — снимок с подписью «Данные на <дата снимка>». Ссылка «Все вакансии» на trudvsem.ru.
6. **«Похожие направления»** — 2–4 строки: код · название · `diff` · зона пользователя. Кнопка **«Сравнить»** (добавляет обе программы в сравнение).

### 6.5. Сравнение `/compare`
До 3 колонок. Строки (ровно эти, в таком порядке): Зона и запас · Проходной 2025 и тренд · Бюджетных мест · Зарплата через год · Зарплата через 5 лет · Трудоустроены · Чему научат (первое предложение). Лучшее значение в строке — жирным с точкой акцента. На мобильном — горизонтальный скролл-снап по колонкам с фиксированной первой колонкой подписей. Кнопка «В план» под каждой колонкой. Пустое состояние: «Добавь направления для сравнения из карточки направления».

### 6.6. План Б `/plan-b`
Вертикальное дерево (4 ветки), у каждой: заголовок, 1 фраза, «Сроки», «Плюсы», «Минусы», «Что сделать» (чек-лист):
1. **Дополнительный набор** — примерно с 12 августа; следить за вузами с незаполненными местами. Показать вузы из плана пользователя, где его зона `reach` ближе всего к проходному.
2. **Платное обучение с переводом на бюджет** — после 1 курса при хорошей успеваемости и наличии мест; честно: перевод не гарантирован.
3. **Колледж → вуз** — поступление по аттестату, приём на свободные места до 25 ноября.
4. **Год на подготовку** — ЕГЭ действует 4 года, можно пересдать и улучшить результат. Честно: для юношей — вопрос отсрочки от армии (без юридических советов, ссылка «уточни в военкомате»).

Рекомендуемая ветка подсвечивается по профилю (например, если есть `reach` с `margin > -15` — допнабор).

### 6.7. `/admin` — мини-аналитика
Скрытый маршрут (нет в навигации), защищён токеном из `ADMIN_TOKEN` (ввод в форме, хранится в sessionStorage). Если токен не задан в окружении — страница доступна с баннером «Демо-режим».
- Воронка по событиям из раздела 8 (столбцы + конверсия шаг-к-шагу).
- Топ-10 открываемых кодов.
- **Топ-10 сравниваемых пар** — главный продуктовый инсайт.
- Распределение вердиктов.
- Переключатель периода: 24 часа / 7 дней / всё время.
- Кнопка «Заполнить демо-событиями» (только в демо-режиме) — генерирует 500 синтетических сессий, помеченных `synthetic=1`, чтобы на защите экран не был пустым; фильтр «Скрыть синтетические».

## 9. Бэкенд и API

Один процесс Hono на Node 20, порт `8080`. Отдаёт собранный фронт (`apps/web/dist`) как статику с SPA-фолбэком на `index.html`, и API под `/api`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | `{ status, version, snapshotDate, uptime }` |
| `GET /api/meta` | даты кампании, пороги зон, дата снимка данных |
| `GET /api/regions` | регионы |
| `GET /api/directions?q=` | справочник направлений, поиск по коду и названию |
| `GET /api/universities?region=` | вузы |
| `GET /api/programs?region=&code=&universityId=` | программы (демо + реальные поверх) |
| `GET /api/programs/:id` | программа + вуз + контент + зарплаты (регион с фолбэком на RU) |
| `GET /api/salaries/:code?region=` | зарплаты выпускников |
| `GET /api/vacancies?code=&region=` | прокси к API «Работа России» |
| `POST /api/plan` | `buildPlan` на сервере (та же функция из `core`) — для шаринга и тестов |
| `POST /api/events` | приём аналитики |
| `GET /api/admin/stats` | агрегаты (заголовок `Authorization: Bearer <ADMIN_TOKEN>`) |
| `POST /api/admin/seed` | синтетические события (только демо-режим) |
| `GET /api/openapi.json` | спецификация, сгенерированная из zod-схем |

### 9.1. Прокси «Работа России»
- URL: `http://opendata.trudvsem.ru/api/v1/vacancies/region/{trudvsemCode}?text={vacancyQuery}&limit=20` (ключ не нужен; ответ — `results.vacancies[].vacancy` с полями `job-name`, `salary_min`, `salary_max`, `company.name`, `vac_url`, `creation-date`).
- Таймаут 4 с, кэш в памяти (LRU) и в SQLite на 6 часов.
- При ошибке/таймауте — последний кэш (`source: "cache"`), иначе `data/snapshot/vacancies_sample_nn.json` или пустой список (`source: "snapshot"`). **Эндпоинт никогда не отдаёт 5xx из-за внешнего API.**
- Нормализованный ответ: `{ source, fetchedAt, total, items: [{ title, company, salaryMin, salaryMax, url }] }`.

### 9.2. Wikidata
Вузы уже в снимке. Фоновое обновление (опционально, за флагом `REFRESH_WIKIDATA=true`) — раз в сутки, с таймаутом и сохранением только при успешном ответе. По умолчанию выключено.

### 9.3. Отказоустойчивость фронта
Фронт импортирует снимок данных напрямую из `data/snapshot` (через `packages/data`) и считает план в браузере. API используется для вакансий, аналитики, актуального снимка. **Если `/api` недоступен — весь сценарий, кроме живых вакансий и аналитики, работает.** Проверяется E2E-тестом с заблокированной сетью к `/api/*`.

**Фаза 8 — Документация (≈1,5 ч).** Раздел 13.
