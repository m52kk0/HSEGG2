# Тестирование

```bash
pnpm test           # юниты, данные, API, компоненты — 299 проверок
pnpm test:cov       # то же с покрытием и порогом по ядру
pnpm e2e            # Playwright: 48 проверок на мобильном и десктопе
pnpm lint           # ESLint + stylelint
pnpm typecheck      # tsc по всем проектам
pnpm docker:smoke   # сборка образа, запуск и проверка эндпоинтов
```

Всё вместе прогоняется в CI (`.github/workflows/ci.yml`) тремя параллельными задачами.

---

## Уровни

| Уровень | Инструмент | Где лежит | Что проверяет |
| --- | --- | --- | --- |
| Ядро | Vitest | `packages/core/src/__tests__/` | баллы, прогноз, зоны, план, вердикты, предупреждения, симуляция, шаринг |
| Инварианты | Vitest | `packages/core/src/__tests__/plan-invariants.test.ts` | свойства плана на 400 случайных мирах |
| Данные | Vitest + zod | `packages/data/src/__tests__/` | схемы снимка, ссылочная целостность, детерминизм генератора, демо-сценарий |
| API | Vitest + `app.request()` | `apps/api/src/__tests__/` | все эндпоинты, 400 на кривой ввод, фолбэки вакансий, rate-limit, доступ к админке |
| Компоненты | Vitest + Testing Library | `apps/web/src/ui/__tests__/` | UI-кит: зоны, состояния кнопок, тултип, валидация ввода |
| E2E | Playwright | `e2e/*.spec.ts` | сценарии целиком на 390×844 и 1280×800 |
| Доступность | `@axe-core/playwright` | `e2e/a11y.spec.ts` | 0 нарушений serious и critical на 8 экранах |
| Контейнер | Node-скрипт | `scripts/docker-smoke.mjs` | build → run → health → SPA → вакансии → не root |

## Покрытие ядра

Порог задан в `vitest.config.ts` и роняет сборку, если покрытие ниже:

```
packages/core/src/**: statements 95, branches 90, functions 95, lines 95
```

Фактическое покрытие — 99% операторов и 98% ветвей. HTML-отчёт после `pnpm test:cov`
лежит в `coverage/index.html`.

## Инвариантные тесты

Примерные тесты проверяют разобранные случаи, инвариантные — свойства, которые обязаны держаться
на любых данных. Генератор миров использует фиксированный seed, поэтому падение всегда
воспроизводимо: перезапуск даёт тот же набор входов.

Список свойств — в [ALGORITHM.md](ALGORITHM.md#9-инварианты-закреплённые-тестами).

## E2E

Тесты идут против **собранного** фронта (`vite preview`), как он поедет в контейнер. API при этом
намеренно не поднимается: сценарий обязан проходиться без него.

Что проверяется:

1. Онбординг из 4 шагов доводит до плана; у НГТУ видны 15.03.04 и 13.03.02 с ожидаемыми зонами.
2. Карточка направления: график, зарплаты, похожие направления; переход в сравнение; ровно те
   строки сравнения и в том порядке, который задан в ТЗ.
3. «Поделиться планом»: ссылка из буфера обмена открывается в чистой сессии и даёт тот же вердикт.
4. Правка плана мгновенно меняет вердикт, приоритеты перенумеровываются.
5. Слабые баллы → вердикт риска → предупреждение → План Б со сроками.
6. Поиск по коду `15.03.04` и по названию; пустой результат объясняет, что делать.
7. **Заблокированный `/api/*`**: план, график, зарплаты, сравнение и План Б работают; вакансии
   показывают честную плашку.
8. Несколько регионов: предупреждение называет регионы, у чужих вузов метка «другой регион».
9. Клавиатура: онбординг и раскрытие карточки вуза; видимый фокус.
10. Тач-цели не меньше 44px, горизонтального скролла нет ни на одном экране.

### Запуск без загрузки браузера

Если сборка Chromium не скачивается (закрытая сеть), можно взять уже установленный браузер:

```bash
PLAYWRIGHT_CHANNEL=msedge pnpm e2e
```

В CI переменная не задаётся и работает обычный Chromium (`pnpm e2e:install`).

### Отладка

```bash
pnpm e2e -- --ui                             # интерактивный режим
pnpm e2e -- --project=mobile -g "План Б"     # один сценарий
npx playwright show-trace test-results/.../trace.zip
```
