# Аналитика

Продуктовая аналитика нужна, чтобы понять, где абитуриент застревает и между чем он реально
выбирает. Персональные данные для этого не нужны, поэтому их здесь нет.

---

## Что НЕ собираем и почему

| Не собираем | Почему |
| --- | --- |
| Имя, e-mail, телефон | Не нужны для ценности продукта, но делают систему объектом 152-ФЗ |
| IP-адрес и user-agent | Из них восстанавливается личность и устройство; для воронки бесполезны |
| Точные баллы ЕГЭ | Балл + регион + направление — почти идентификатор. Отправляем только корзину |
| Связку «человек → вуз» | В событиях есть только коды направлений |
| Cookies и сторонние трекеры | Внешних скриптов в прототипе нет вовсе |

Баллы уходят только корзиной: `<200`, `200-239`, `240-269`, `270+`.

`sessionId` — случайный UUID из `localStorage`. Он не связан ни с чем, кроме самого себя,
и исчезает при нажатии «Начать заново».

## События

| Событие | Свойства | Когда |
| --- | --- | --- |
| `onboarding_start` | — | нажата кнопка «Построить план» на первом экране |
| `onboarding_step` | `step` (1–4) | открыт шаг онбординга |
| `onboarding_complete` | `scoreBucket`, `interestsCount`, `regionMode` | профиль собран |
| `plan_view` | `verdict`, `universities`, `hasSafe` | показан экран плана |
| `plan_edit` | `action` | план изменён вручную |
| `program_open` | `code`, `zone` | открыта карточка направления |
| `compare_open` | `codes` (отсортированы), `count` | открыто сравнение |
| `planb_open` | `verdict` | открыт План Б |
| `vacancies_loaded` | `source`: `live` / `cache` / `snapshot` | блок вакансий получил данные |
| `plan_share` | `method`: `link` / `print` | план скопирован или отправлен на печать |

Значения `action` у `plan_edit`: `move_up`, `move_down`, `remove_program`, `add_program`,
`add_university`, `remove_university`.

Список закрыт: сервер валидирует имена событий по перечислению и отвечает `400` на незнакомое.
Значения свойств — только строки, числа и логические значения; вложенный объект тоже даёт `400`.

## Как это работает

**Клиент** (`apps/web/src/lib/analytics.ts`): события копятся в очереди и уходят батчами раз
в 5 секунд, а также при `visibilitychange` и `pagehide`. Отправка — через `navigator.sendBeacon`,
с фолбэком на `fetch` с `keepalive`. Любая ошибка проглатывается: аналитика не имеет права
ломать сценарий.

**Сервер** (`POST /api/events`): до 50 событий за раз, валидация zod, rate-limit 60 запросов
в минуту на сессию (в памяти). Данные пишутся в SQLite:

```sql
events(id, session_id, name, props_json, created_at, synthetic)
```

Клиентское время принимается, только если оно не из будущего — иначе подставляется серверное.

## Экран `/admin`

Скрытый маршрут: в навигации его нет. Защищён токеном `ADMIN_TOKEN`, который вводится в форме
и хранится в `sessionStorage` вкладки. Если токен в окружении не задан, страница открыта
и показывает баннер «Демо-режим».

Что на экране:

- **Воронка** — вложенная: каждый шаг считается по сессиям, прошедшим все предыдущие. Без этого
  вход по ссылке «Поделиться планом» давал конверсию 300%, потому что план виден без онбординга.
- **Действия вне воронки** — правка плана и переход в План Б. Они случаются на любом шаге,
  поэтому в воронку их ставить нельзя: она перестала бы убывать.
- **Топ-10 открываемых направлений**.
- **Топ-10 сравниваемых пар** — главный продуктовый инсайт: между чем именно люди выбирают.
  Именно отсюда берутся идеи, какие «похожие направления» описывать редакционно.
- **Распределение вердиктов** — сколько абитуриентов приходит с реальным риском.
- Переключатель периода: 24 часа / 7 дней / всё время.
- Тумблер «Показывать синтетические».

### Синтетические события

Кнопка «Заполнить демо-событиями» (только в демо-режиме) создаёт 500 сессий, помеченных
`synthetic = 1`, чтобы на защите экран не был пустым. Генератор детерминирован, шаги вложены
друг в друга, поэтому воронка убывает как настоящая. Повторный вызов заменяет предыдущую
синтетику, а не накапливает её.

## Яндекс Метрика

Заготовка: если задана переменная `VITE_YM_ID`, `track()` дополнительно вызывает
`ym(id, 'reachGoal', event, props)`. Скрипт Метрики подключается только при наличии ID.

В MVP переменная **пустая** и никакой внешний скрипт не загружается — это осознанно: внешних
CDN и трекеров в прототипе нет. Чтобы включить, задай `VITE_YM_ID` при сборке фронта и добавь
загрузку счётчика в `apps/web/index.html`.
